# Hiking G1 to X2 port audit (independent reviewer, read only, 2026-11-11)

What I compared: the G1 run's `params/env.yaml` (desktop, `g1_parkour/20261111_134929_.../params/env.yaml`; all G1 resumes have the same env.yaml) against X2 run 2 (`runs/x2_parkour_v2/20261111_225809/params/env.yaml`) and run 3 (`runs/x2_parkour_v3/20261112_015119/params/env.yaml`), key by key. agent.yaml is the same apart from run name and iteration count. I checked the X2 values against `x2_port/robot/x2_ultra_pelvis_root.urdf`, the port code (`files_instinctlab/assets/agibot_x2.py`, `config/x2/*.py`) and both motion files (X2 v2 npz on the node, G1 release npz on the desktop). I ran no training and used no GPU. On the node CPU I ran two short read-only scripts: hull overlap by forward kinematics, and reference statistics.

**No wrong body or joint names.** Every name resolves to the intended X2 body. Joint order is mapped by name everywhere. The flaws are in what the X2 is asked to imitate and in what the X2 is penalised for.

## Checked and correct (cleared)

- Body names: `.*_ankle_roll_link` is the X2 foot (sole hull 0.073 m below the ankle). Contact sensor on `Robot/.*`, 1 N threshold, air time tracked. `base_contact` on `torso_link`. Height scanners on `ankle_roll_link`, offset x 0.04 (sole centre 0.037). Volume points lie inside the sole. `undesired_contacts` excludes the feet.
- `feet_air_time` has no size-dependent threshold: it is the min mode time in single stance, gated at 0.15 m/s. Run 3 uses the unstaged function (option e is off), as intended.
- Joint order: actions, observations and the AMP observation are matched by name. The motion loader maps the npz `joint_names` to Isaac `dof_names` by name. Mirror map and signs check against the URDF axes and limits (roll and yaw negate, pitch keeps). Link mirror map has the same pattern as the G1's.
- AMP frames: the robot and the reference are both pelvis-based. Base velocities are in the base frame on both. Quaternion converted xyzw to wxyz correctly. 50 Hz.
- Same on both robots: no reference-state initialisation, reset ranges, spawn drop of about 7 cm. Curriculum rule identical, with no robot numbers. Commands identical apart from option c. sim dt, decimation and solver iterations identical. agent.yaml identical (PPO, AMP, `init_noise_std`).
- `pelvis_orientation_l2` moved to `torso_link`: correct. `feet_close_xy` threshold 0.12 against X2 foot spacing of 0.274 m: fine. Camera, crop and range changes are the listed run-2 departures.
- Seam spikes in the reference (100 frames over 15 rad/s, 16 frames over 3 m/s base speed) are like the G1 release's (114 and 52). Not X2-specific.

## Cheapest checks for the coordinator (CPU or one short pass)

1. Drop `head_*` from the AMP observation (`joint_names` on `amp_policy` and `amp_reference`), or log head joint speed for a stander and a walker.
2. Build the X2 default pose from the reference mean (or rebuild the reference with an upright waist and arms near the default), as the G1 pair is.
3. Either use the G1 action range (scale from effort / actual kp, or scale `action_rate` by scale squared), or note the 2-4x higher step cost as a departure.
4. Run a contact census in Isaac for a scripted stepping pose: hip roll -0.2, hip yaw +-0.3, and the reference arm pose.
